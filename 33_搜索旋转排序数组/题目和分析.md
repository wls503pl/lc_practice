## 题目

Link: https://leetcode.cn/problems/search-in-rotated-sorted-array/description/

整数数组 nums 按升序排列，数组中的值 互不相同 。

在传递给函数之前，nums 在预先未知的某个下标 k（0 <= k < nums.length）上进行了 向左旋转，使数组变为 [nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]（下标 从 0 开始 计数）。例如， [0,1,2,4,5,6,7] 下标 3 上向左旋转后可能变为 [4,5,6,7,0,1,2] 。

给你 旋转后 的数组 nums 和一个整数 target ，如果 nums 中存在这个目标值 target ，则返回它的下标，否则返回 -1 。

你必须设计一个时间复杂度为 O(log n) 的算法解决此问题。

 

示例 1：

输入：nums = [4,5,6,7,0,1,2], target = 0
输出：4

示例 2：

输入：nums = [4,5,6,7,0,1,2], target = 3
输出：-1

示例 3：

输入：nums = [1], target = 0
输出：-1

 

提示：

    1 <= nums.length <= 5000
    -104 <= nums[i] <= 104
    nums 中的每个值都 独一无二
    题目数据保证 nums 在预先未知的某个下标上进行了旋转
    -104 <= target <= 104

## 分析

**先说结论:旋转和"能不能用二分"的关系**

普通的有序数组二分很简单:比较 nums[mid] 和 target,一边扔一边留。

旋转之后,数组不再整体有序了,比如 [4,5,6,7,0,1,2]。如果你只看 mid 和 target 的大小关系,没法直接判断该往左走还是往右走——因为你不知道 mid 落在"前半段"还是"后半段"。

*这道题真正考的不是"如何处理旋转",而是:"局部有序"下,如何设计判断条件来决定二分的方向。*
---

**关键观察:虽然整体不是有序的,但一分为二后,必有一半是有序的**

这是本题的核心突破口。任取一个 mid,数组被分成 [left, mid] 和 [mid, right] 两部分,这两部分中至少有一部分是严格递增(有序)的。

证明也很直觉:旋转数组只有一个"断点"(即最大值到最小值的跳变处)。把数组从中间切一刀,断点只能落在左半或右半其中一边,不可能同时在两边都存在断点。所以没有断点的那一半,一定是有序的。
---

**怎么\"过滤障眼法\"**

拿到这道题容易被绕进去的几个点,你可以这样过滤:

1. 不要试图先"找旋转点"再二分
两次二分:先找断点在哪,把数组切成两段有序数组,确定 target 在哪一段里,再对那一段做一次标准二分查找。——绕了两步。

2. 核心判断逻辑就是三步
每次循环:

判断 [left, mid] 是不是有序的:nums[left] <= nums[mid]
如果有序,再判断 target 是否落在 [nums[left], nums[mid]) 区间内
在,则 right = mid - 1
不在,则 left = mid + 1
如果 [left, mid] 不是有序的,那么 [mid, right] 一定有序,同理判断 target 是否落在 [nums[mid], nums[right]] 内

3. 等号的坑
判断 nums[left] <= mid 时用 <= 而不是 <, 因为当区间只剩一个元素(left == mid)时也要认为它是 "有序" 的, 否则会漏判。

一次二分:不管断点在哪,每次都看当前这一半 [left, mid] 是不是有序的,直接根据这个"有序性"来判断 target 该往左找还是往右找,一步到位。——只走一遍。
一句话:别想着先"拆开"再"查",直接边查边判断哪边是有序的就够了。
